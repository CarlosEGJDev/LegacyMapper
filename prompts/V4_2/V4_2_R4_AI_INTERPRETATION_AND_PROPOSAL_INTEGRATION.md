# 2. Objective

Integrate the existing AI interpretation capability into the V4.2 `full`
pipeline as an EXPLICITLY OPT-IN stage.

The intended boundary is:

deterministic evidence/context
        ↓
AI interpretation
        ↓
Proposal
        ↓
STOP
        ↓
Technical Lead approval (NOT R4)

R4 must NOT create canonical knowledge.

R4 must NOT execute R11/R12 projections.

`full` run.

# 14. AI Failure Policy

AI is optional.

Therefore:

deterministic pipeline SUCCESS
+
AI interpretation FAILED

must normally produce:

RunStatus.PARTIAL

not FAILED.

All deterministic documents and indexes must remain available.

If AI interpretation fails:

record structured StageError
do not write fabricated proposal
mark proposal stage skipped
continue FINAL_SUMMARY

Provider unavailability is an explicit partial result, not a reason to lose
the deterministic analysis.

# 16. Prompt/Data Discipline

Inspect how `deep_interpretation.py` constructs prompts.

Ensure AI input is based on evidence from the current run.

Do not send unrelated repository data if a smaller context package already
exists.

Do not let the AI modify source code.

AI output must be treated as untrusted structured interpretation.

Validate it before converting it into Proposal records.

Malformed AI output must produce a structured failure/partial result.

Never silently repair meaning-changing malformed output.

# 17. Determinism Boundary

AI text itself is non-deterministic.

Do not falsely claim AI-enabled runs are byte-deterministic.

Instead:

deterministic analysis artifacts remain deterministic
proposal envelope/serialization ordering remains deterministic for a given
validated AI result
AI semantic content is explicitly NON_DETERMINISTIC

Document this boundary.
